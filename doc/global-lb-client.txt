Global LB v2 nonblocking transport
=================================
UD-007/011 v2-only-20261004; USE_GLOBAL_LB.

One existing worker thread-0 task owns one nonblocking RESP2 TCP connection.
It uses HAProxy's fd/task scheduler and async DNS; no extra OS thread or
synchronous network call is introduced on a traffic thread.

The reservation lifecycle supplies START, TAKE, RELEASE, CANCEL, HEARTBEAT,
RESTORE and STOP. There is one command in flight. Unconfirmed TAKE commands
are not replayed; failure invalidates admission until a fresh coherent local
ledger is restored. UUID is generated once after fork and retained on reconnect.

I/O is bounded by bytes/calls per invocation. The command deadline is capped
by the remaining reservation deadline. Queue+send+reply therefore share the
reserve budget. Shutdown separately caps cleanup at100ms before native streams
are closed. Healthy established TCP streams survive a state-store outage.

DNS hostnames require resolvers default; numeric IPv4/IPv6 is also supported.
No AUTH, TLS, Cluster or Sentinel support is included. The store must be private.

See doc/global-lb-reservation.txt for protocol, limits and lifecycle semantics.
Transport regressions run through the actual production lifecycle:
  python3 tests/unit/global-lb-v2-native.py /absolute/path/haproxy valkey/valkey:9.1.1-alpine
  python3 tests/unit/global-lb-v2-lifecycle.py /absolute/path/haproxy valkey/valkey:9.1.1-alpine
Repeat with redis:7.2-alpine. Fixtures own isolated stores and loopback sockets.
The obsolete v1 and test-only lifecycle drivers have been removed.
