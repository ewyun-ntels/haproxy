Global LB configuration (v2 only)
================================
UD-007/010 v2-only-20261004; USE_GLOBAL_LB / USE_GLOBAL_LEASTCONN.

The only Global LB runtime is atomic reservation v2. Enabling
USE_GLOBAL_LEASTCONN implies USE_GLOBAL_LB. A common-only build exposes local
diagnostics/parser helpers but cannot select balance global-leastconn.

A backend opts in with balance global-leastconn and global-lb fallback leastconn.
The global section requires state-store and a unique instance-id. No timer
directive is required to select v2. Ordinary native backends do not start the
state-store client. Only equal-weight TCP backends are supported.

See examples/global-lb-v2.cfg, charts/haproxy-global-lb/values.yaml and
doc/global-lb-reservation.txt for the full contract and deployment values.
The production example/chart explicitly use reserve=1s and command=1s; C
omission defaults remain100ms. Heartbeat=300ms, instance-timeout=3s,
connect=200ms, reconnect=100ms..5s and jitter=20%.

The removed v1 directives sync-interval, snapshot-ttl, stale-after and
recovery-successes are rejected. The periodic cache CLI is removed.
An old binary can be recovered from Git; this runtime does not emulate v1.
Apply configuration by deliberate restart/Pod replacement, never live reload.

Validation:
  sh tests/unit/global-lb-config-unit.sh
  sh tests/unit/global-lb-config.sh /absolute/path/haproxy on
  sh tests/unit/global-lb-config-v2.sh /absolute/path/haproxy on
Repeat with common-only and feature-OFF builds (use off for the latter).
